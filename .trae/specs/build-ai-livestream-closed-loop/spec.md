# AI 直播闭环（平台接入 + 决策中枢 + 实时策略优化）Spec

## Why

当前系统弹幕来自前端模拟输入、前端只能 REST 轮询获取提词建议、决策结果与效果数据不落库，无法接入真实直播平台，也无法基于实时效果优化策略。本 spec 建立「真实弹幕接入 → 决策中枢 → 数字人口播展示 → 效果回流优化」的商用闭环地基。

## SIPOC 业务流程框架

```
Supplier(供应方)        Input(输入)           Process(过程)                Output(输出)           Customer(客户)
──────────────        ──────────           ──────────────               ─────────────         ─────────────
直播平台弹幕     ──►   弹幕消息流     ──►  ①平台接入网关(统一消息模型)  ──►  数字人口播/动作  ──►  观众(转化)
商品库(MySQL)   ──►   商品数据       ──►  ②决策中枢(LLM理解+融合)      ──►  监场台提词       ──►  运营/监场人员
整场剧本        ──►   直播阶段状态   ──►  ③导演脚本生成                ──►  策略调整记录     ──►  商家(GMV)
后台数据        ──►   人气/点击/转化 ──►  ④TTS/数字人展示适配          ──►  效果报表              ──►
                                      ⑤策略引擎(实时调权)
```

## What Changes

- **新增平台接入网关**：适配器模式接入直播平台——官方开放平台 API（抖音/淘宝/快手，按资质可用性启用）、浏览器端采集兜底方案、模拟弹幕源（开发/演示用）；统一弹幕与实时数据消息模型
- **新增直播场次（LiveSession）域**：场次创建/状态机管理、弹幕流与决策记录持久化到 MySQL
- **新增 WebSocket 实时通道**：弹幕、决策指令、实时指标服务端推送，替代前端 REST 轮询
- **决策中枢升级**：互动理解从关键词匹配升级为 LLM 语义分析（保留规则降级）、融合整场剧本与商品信息、输出结构化「导演脚本」（台词/情绪/动作/节奏/商品卡）
- **新增展示适配层**：TTS 语音合成 + 2D 数字人形象驱动（MuseTalk/LivePortrait 实时口型，底版素材支持真人录制/照片/AI 生成三种来源），无 GPU 时降级为纯声音形态
- **新增实时数据反馈闭环**：效果/人气/转化指标采集入库、策略引擎按指标动态调整决策权重
- **前端监场台改版**：WebSocket 实时展示 + 实时指标看板 + 一键接管/人工兜底
- **合规模块前移**：作为 TTS/展示输出的强制闸门（现有能力复用，位置调整）

无破坏性变更：现有 REST API（商品管理、agent/decide、RAG）保持兼容，agent/decide 保留作为无状态降级通道。

## Impact

- Affected specs：无既有 spec，本项目首次建立
- Affected code：
  - `backend/app/models/`：新增 LiveSession、DanmakuMessage、DecisionRecord、LiveMetric 表
  - `backend/app/services/`：新增 `gateway/`（平台接入）、`director/`（导演脚本/剧本）、`strategy/`（策略引擎）
  - `backend/app/api/v1/`：新增场次、网关管理路由；新增 WebSocket 端点
  - `backend/app/core/config.py`：新增平台适配器、TTS、策略相关配置
  - `frontend/src/`：监场台页面改版、WebSocket 客户端
  - `docker/docker-compose.yml`：视策略引擎需要评估是否引入 Redis（二期，不强依赖）

## ADDED Requirements

### Requirement 1: 平台接入网关（Gateway）

系统 SHALL 提供统一平台接入层，以适配器模式隔离不同弹幕来源，输出统一消息模型。

- 官方 API 适配器：预留抖音开放平台、淘宝开放平台（ISV）、快手开放平台适配器接口与配置占位；实际启用以平台资质审批通过为前提，资质未获批时 SHALL 保持禁用状态并可配置开关
- 浏览器采集适配器：作为无官方渠道时的兜底方案，通过浏览器端脚本采集直播页评论并回传网关；SHALL 在文档中明确平台风控与条款风险提示
- 模拟弹幕源：SHALL 提供内置模拟适配器，支持按场景回放弹幕序列（如高频提问、负面刷屏、购买意向），供开发与演示
- 统一消息模型：所有来源的弹幕 SHALL 归一化为 `{session_id, platform, user_id(脱敏), content, timestamp, raw}` 结构；实时指标归一化为 `{metric_type, value, timestamp}`
- 网关 SHALL 具备断线重连与消息缓冲能力，重连期间消息不丢失（本地缓冲队列）

#### Scenario: 模拟源驱动全链路
- **WHEN** 使用模拟弹幕源向指定场次注入弹幕序列
- **THEN** 弹幕经统一消息模型进入决策中枢，全链路行为与真实平台来源一致

#### Scenario: 适配器切换
- **WHEN** 配置文件切换弹幕来源适配器（mock ↔ browser ↔ official）
- **THEN** 决策中枢与前端无感知，无需修改代码

### Requirement 2: 直播场次（LiveSession）与数据持久化

系统 SHALL 引入直播场次概念，弹幕与决策全量落库。

- 场次模型：`LiveSession{id, title, platform, status(待开播/直播中/已结束/异常), started_at, ended_at, current_stage}`
- 每条弹幕持久化为 `DanmakuMessage`，每条决策输出持久化为 `DecisionRecord{id, session_id, trigger_reason, script(导演脚本JSON), compliance_result, adopted(采纳状态), created_at}`
- 场次结束 SHALL 支持查询整场弹幕回放与决策历史

#### Scenario: 场次生命周期
- **WHEN** 创建场次并开始直播
- **THEN** 后续弹幕、决策、指标均关联该场次；结束时场次状态置为已结束，数据可回放查询

### Requirement 3: WebSocket 实时通道

系统 SHALL 提供 WebSocket 端点（`/ws/live/{session_id}`），服务端主动推送替代前端轮询。

- 推送消息类型：`danmaku`（新弹幕）、`decision`（导演脚本/提词）、`metric`（实时指标）、`stage`（阶段变更）
- 客户端断线 SHALL 自动重连并携带 last_event_id 补拉增量
- 保留 REST `POST /agent/decide` 作为无状态降级通道，行为与现有兼容

#### Scenario: 实时提词推送
- **WHEN** 决策中枢生成导演脚本
- **THEN** 监场台前端在 1 秒内通过 WebSocket 收到该指令

### Requirement 4: 决策中枢升级（LLM 互动理解 + 导演脚本 + 剧本融合）

决策中枢 SHALL 升级为 LLM 驱动，并输出面向数字人的结构化导演脚本。

- 互动理解：LLM 对弹幕批量做意图识别、情绪分析、高频问题聚合；LLM 超时或失败时 SHALL 自动降级到现有规则/关键词方案，降级事件记录日志
- 导演脚本输出格式（结构化 JSON）：`{lines: [{text(台词), emotion(情绪), action(动作建议), pace(语速)}], show_product_card(是否弹商品卡), priority, trigger_reason}`
- 剧本融合：SHALL 支持导入整场剧本（阶段划分 + 每阶段目标/话术要点），决策时作为上下文输入；结构引擎的阶段切换受剧本约束
- 商品信息融合：沿用现有商品库（MySQL），决策上下文注入当前讲解商品
- 全链路延迟目标：弹幕进入 → 导演脚本产出 ≤ 2 秒（不含推流缓冲）

#### Scenario: LLM 降级
- **WHEN** LLM API 超时或异常
- **THEN** 决策中枢在 500ms 内降级为规则方案继续产出脚本，且产出结果标记 `degraded=true`

#### Scenario: 剧本约束
- **WHEN** 导入了带阶段规划的剧本且直播进行到促单阶段
- **THEN** 决策输出的台词风格与动作建议符合促单阶段目标

### Requirement 5: 展示适配层（TTS + 2D 数字人形象驱动）

系统 SHALL 提供展示适配层，将导演脚本转换为可播出的数字人口播内容。

- TTS 引擎适配器（可配置：开源 CosyVoice 或商用 API）合成台词音频，同时产出字幕序列；合成前 SHALL 强制通过合规模块（违禁词过滤 + 替代方案），合规不通过的内容不得进入 TTS
- 2D 形象驱动（开源路线）：SHALL 支持以底版素材 + 实时口型驱动模型（MuseTalk / LivePortrait，可配置）将 TTS 音频渲染为数字人视频画面；底版素材 SHALL 支持三种来源——真人录制半身视频（一次性录制 1~3 分钟）、单张照片驱动、AI 生成虚拟形象（Stable Diffusion），并支持 3~5 套素材轮换避免动作循环感
- 台词与形象解耦：底版素材仅为形象"皮"，台词由决策中枢实时生成、TTS 实时合成、驱动模型按音频实时替换嘴部/面部区域，SHALL 保证策略调整与弹幕应答的台词动态性不受素材限制
- 动作指令处理：导演脚本的动作建议 SHALL 映射为画面层操作（切换商品特写贴片、切换底版动作素材、叠加字幕/商品卡），而非实时生成新肢体动作
- 全链路延迟预算：TTS ≤ 0.5s + 口型驱动 ≤ 0.8s + 画面合成 ≤ 0.5s；驱动模型依赖 GPU（配置中声明，支持本地 GPU 或云 GPU 部署形态）
- 合规与平台要求：接入推流前 SHALL 预留"AI 生成内容"标识叠加能力，配置中支持按平台开启数字人报备所需标识
- 输出物：TTS 音频流 + 数字人视频画面流 + 字幕 JSON + 动作指令包；前端播放形态本期以监场台内嵌播放器呈现，RTMP 推流模块为可选扩展
- TTS 与形象驱动均为适配器模式：未配置 GPU/驱动模型时 SHALL 降级为"TTS + 字幕"纯声音形态，不阻塞全链路

#### Scenario: 合规拦截
- **WHEN** 导演脚本台词含违禁词且无可用替代方案
- **THEN** 该条脚本不进入 TTS，监场台收到合规告警并给出人工兜底提示

#### Scenario: 台词动态驱动
- **WHEN** 决策中枢针对新弹幕实时生成一句从未预录的话术
- **THEN** TTS 合成该音频后，驱动模型实时渲染对应口型的数字人画面，观众可听到并看到该动态台词

#### Scenario: 无 GPU 降级
- **WHEN** 部署环境无 GPU 或驱动模型未就绪
- **THEN** 展示层自动降级为 TTS 音频 + 字幕形态，决策与策略链路不受影响

### Requirement 6: 实时数据反馈与策略优化

系统 SHALL 采集实时效果数据并驱动决策策略动态调整。

- 指标采集：人气（在线人数）、互动（弹幕速率、点赞）、转化（购物车点击、下单）入库为 `LiveMetric`；官方渠道可用时从平台 API 拉取，否则由监场台/模拟源手动注入
- 策略引擎：基于滑动窗口指标动态调整决策权重（如人气上升 → 加大促单权重；负面情绪聚集 → 切换安抚/答疑策略），初始提供 3~5 条可配置基础策略规则
- 每次策略调整 SHALL 记录调整原因与前后权重快照，形成可审计的优化轨迹

#### Scenario: 负面情绪响应
- **WHEN** 滑动窗口内负面弹幕占比超过阈值
- **THEN** 策略引擎提升答疑/安抚类指令优先级，并在监场台展示策略调整原因

### Requirement 7: 前端监场台

前端 SHALL 改版为监场台形态。

- WebSocket 实时展示：弹幕流、当前导演脚本（台词/动作/商品卡）、阶段进度
- 实时指标看板：人气/弹幕速率/转化指标曲线
- 人工接管：SHALL 支持监场人员一键暂停自动决策、手动下发话术（同样过合规检查）、一键恢复

#### Scenario: 一键接管
- **WHEN** 监场人员点击"接管"
- **THEN** 自动决策暂停，转由人工输入话术（过合规检查后播出）；点击"恢复"后回到自动模式

## REMOVED Requirements

无。现有功能全部保留。
